# 截图规则

仅 `manual_kind=operation` 有截图阶段。截图必须成为 `截图/` 下的本地图片文件并进入 `截图清单.json`，正式生成只按清单插入，不猜测顺序。

## 方式选择

用户必须在四种方式中显式选择一种并记录 screenshot-method 门禁：

1. `agent-browser`：agent 使用宿主自带的浏览器控制技能或工具操作真实页面截图。适合宿主已具备浏览器工具（如带 Playwright MCP 的环境），无需额外安装。
2. `playwright-cli`：全局安装的 `@playwright/cli@0.1.20` 命令行工具；检查脚本同时探测 PATH 与 `npm prefix -g`，安装后无需重启 coding agent。
3. `user-supplied`：用户自行截图后放入 `软著/用户截图/`，文件名加数字前缀。
4. `skip`：明确跳过；操作手册保留可见截图预留文字，不阻塞正式生成。

门禁脚本不从备注猜测方式，必须显式传 `--method`。

## 截图要求

- 按操作手册模块顺序编号：`01-首页.png`、`02-查询结果.png`；整理脚本按数字前缀排序，中文文件名保留。
- 截取实际视口，不生成缩小后无法阅读的长图；需要展示页面下方内容时滚动后单独截图。
- 截图前确认页面加载完成，不留加载动画、调试面板、权限提示或无关通知。
- 不通过改 DOM、伪造接口响应或注入数据制造不存在的功能；演示数据可以正常展示。
- 每张截图必须落盘且非空；仅在会话中看到图片不算成功。
- 截图完成后运行 shots.py 生成 `截图清单.json`（status 必须为 ok）。
- 失败时报告具体错误，用户可修复重试、换方式或选择跳过。

## agent-browser 约定

宿主浏览器工具负责打开页面、完成真实交互与截屏，但图片必须保存为 `软著/截图原始/` 下的本地文件（多数宿主工具支持把截图写到指定路径）；随后同样运行 shots.py --method agent-browser 整理生成清单。
