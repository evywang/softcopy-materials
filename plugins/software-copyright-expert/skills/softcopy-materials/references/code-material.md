# 代码选择与鉴别材料规则

依据《计算机软件著作权登记办法》第十条：程序和文档的鉴别材料一般由前、后各连续 30 页组成；不足 60 页时提交全部；程序每页不少于 50 行。

## 选择方式

脚本只生成候选清单（按入口、路由、页面、数据交互、状态、组件、通用能力、服务端排序），不默认选择任何文件。模型阅读业务理解、入口、页面与必要源码后，在 `代码文件选择.json` 中填写 `selected` 与 `model_reason`，再交用户确认并记录 code-selection 门禁。

候选发现按内容检测而非扩展名白名单：可读、大小合理、非文档/配置/二进制/生成物的文本文件全部进入候选；未知扩展名同样进入，由模型和用户判断是否属于登记软件。

## 抽取规则

- 按完整文件抽取，不支持只取某个文件的中间行段。
- 移除注释（整行/块/行尾注释、Python 独立 docstring）与空行；字符串字面量中的注释符号（URL 中的 `//`、`#`）与 C 预处理指令保留。注释剥离按扩展名识别语言家族（C 风格、`#` 风格、`--` 风格），未知扩展名按 C 风格处理。
- 已知局限：正则字面量中的 `//`（如 `const re = /\/\//`）会被误判为行注释而截断该行，正则密集的文件建议人工复核。
- 源码行先按制表符 4 空格展开，再按最多 90 显示列确定性折行（全角字符按 2 列），避免 Word 因宽度二次换页造成页数漂移。
- 每页按 55 个物理行估算选材量（满足每页不少于 50 行），该估算只用于决定取材，最终分页由 Word 排版引擎自动完成，不插入人工分页符。
- 已选代码不足 60 页且候选还有富余时，抽取脚本会停止并要求补充选择；候选全部用尽仍不足 60 页时，生成全部代码材料。
- 总页数不少于 60 时输出前 30 页 + 后 30 页合并为一份 `代码.md`。
- 不在代码正文插入文件路径标记；文件来源、行数与材料行范围记录在 `代码提取清单.json/md` 供追溯。
- 选中的文件必须位于项目目录内；候选生成后变为二进制或超大的文件会被跳过并提示。
