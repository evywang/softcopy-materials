# 申请表字段口径

按官网实际表单顺序登记字段，正式输出前逐项确认。

1. 软件全称
2. 软件简称（可选）
3. 版本号
4. 软件分类（应用软件/嵌入式软件/中间件/系统软件/其他）
5. 开发完成日期（YYYY-MM-DD）
6. 开发方式（单独开发/合作开发/委托开发/下达任务开发）
7. 软件说明（原创/修改（含翻译软件、合成软件））
8. 发表状态（已发表/未发表）
9. 首次发表日期（已发表时填写；未发表留空）
10. 著作权人（国家/省市/类型/姓名/证件类型/证件号）
11. 权利范围（全部权利/部分权利）
12. 权利取得方式（原始取得/继受取得）
13. 开发的硬件环境（不超过50字符）
14. 运行的硬件环境（不超过50字符）
15. 开发该软件的操作系统（不超过50字符）
16. 软件开发环境 / 开发工具（不超过50字符，格式：开发环境: <OS>/开发工具: <IDE>）
17. 该软件的运行平台 / 操作系统（不超过50字符）
18. 软件运行支撑环境 / 支持软件（不超过50字符，直接列出运行依赖）
19. 编程语言（不超过120字符）
20. 源程序量（纯数字，登记软件全部源程序总行数，含空行）
21. 开发目的（不超过50字符，不能只写软件名称）
22. 面向领域 / 行业（不超过50字符）
23. 软件的主要功能（500~1300个非空白字符）
24. 软件的技术特点（可选标签 + 不超过100字符描述）
25. 页数（纯数字，实际提交的代码鉴别材料页数）

## 填写口径

- 软件全称、版本号、著作权人、日期类字段必须由用户确认；脚本给出的值只是建议。
- 软件全称建议以「软件」「平台」「系统」结尾；全称与版本号一旦确认，正式文件名、页眉、标题与正文全部以此为准。
- 项目版本低于 V1.0 时提醒用户：软著首次提交通常建议 V1.0，由用户决定填 V1.0 还是项目当前版本。
- 软件开发环境 / 开发工具只填 IDE（如 Visual Studio Code、WebStorm），禁止填 React、Vite、TypeScript 等技术栈。
- 源程序量按分析得到的全部源码行数（含空行）给出建议值；与已抽取材料行数无关。
- 页数在前30页+后30页模式下为 60；候选源码不足 60 页时为全部材料页数。正式生成会以 Word 实际分页回写修正。
- 编程语言由项目分析的扩展名统计生成建议值，用户可修改。

## 一致性

- 业务理解、代码选择、申请表或最终草稿在确认后被修改时，对应门禁指纹失效，必须重新确认。
- 主要功能、开发目的、行业、技术特点优先取自业务理解阶段模型撰写并通过校验的内容，脚本不做扩写或填充。
