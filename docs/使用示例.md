# softcopy-materials 使用示例

本文把 skill 全流程的真实命令逐步展开，便于理解与排查。**正常使用不需要手敲命令**：把 skill 装进 agent 后，在打开目标项目的会话里说一句"使用 softcopy-materials 为当前项目生成软著材料"，agent 会按 SKILL.md 驱动流程，并在每个门禁处停下等你确认。

约定：

- 命令都在**目标项目根目录**下执行；输出目录 `软著/` 生成在当前目录。
- `<SKILL_DIR>` 替换为 skill 安装目录（含 SKILL.md 的文件夹）；`<PYTHON>` 替换为 Python 3.10+ 解释器，示例直接写 `python`。
- 示例中的公司、项目均为虚构。

## 示例 A：有界面软件 → 操作手册

背景：`D:\works\wms-web` 是一个仓库管理 Web 项目（Vue 前端 + Node 服务），登记名称 **智慧仓储管理平台 V1.0**，著作权人 示例科技有限公司，未发表。宿主 agent 具备浏览器控制、PDF 阅读、视觉能力、联网搜索与 archify 技能。

### 1. 安装自检与环境探测

```bash
python "<SKILL_DIR>/scripts/setup_officecli.py"
python "<SKILL_DIR>/scripts/probe_env.py" --out-dir 软著 --host-tools "browser,pdf-reader,vision,search,archify"
```

探测报告 OfficeCLI 版本就绪（不低于 `1.0.151` 且主版本为 `1`）后，按用户决定记录第一道门禁：

```bash
python "<SKILL_DIR>/scripts/confirm_gate.py" --workdir 软著 --stage environment --note "OfficeCLI 已就绪，继续"
```

（若 OfficeCLI 未安装，探测脚本会以 STOP_FOR_USER 停止并给出安装命令；装完须重启 agent 再探测。）

### 2. 定位与分析项目

当前目录只有一个项目根，无需选择、无 `project` 门禁：

```bash
python "<SKILL_DIR>/scripts/analyze_project.py" --project . --out 软著/analysis/project.json
```

### 3. 业务理解（`business` 门禁）

先收集证据并生成模型稿模板：

```bash
python "<SKILL_DIR>/scripts/business_context.py" --project . --analysis 软著/analysis/project.json --software-name "智慧仓储管理平台" --out-dir 软著/草稿
```

首次运行到此停止：

```text
STOP_FOR_USER
NEXT_ACTION: 模型阅读证据与必要源码后填写模型稿 JSON，再用 --model-context 生成业务理解。
```

模型阅读 README、页面文案、路由与必要源码，填写 `软著/草稿/业务理解模型稿.json`（`manual_kind=operation`、行业、主要功能 500~1300 字、每个页面模块至少两段亲写段落等），然后：

```bash
python "<SKILL_DIR>/scripts/business_context.py" --project . --analysis 软著/analysis/project.json --software-name "智慧仓储管理平台" --out-dir 软著/草稿 --model-context 软著/草稿/业务理解模型稿.json
```

脚本生成 `业务理解.md/json` 后停止等用户确认（含 operation/design 文档类型）；确认后：

```bash
python "<SKILL_DIR>/scripts/confirm_gate.py" --workdir 软著 --stage business --note "确认为仓储行业操作手册"
```

### 4. 代码选择与抽取（`code-selection` 门禁）

```bash
python "<SKILL_DIR>/scripts/code_selection.py" --project . --out-dir 软著/草稿
```

模型在 `代码文件选择.json` 中勾选 `selected` 并为每个文件填写 `model_reason`（优先入口、路由、页面、数据交互；不足 60 页再补服务端源码），用户确认后：

```bash
python "<SKILL_DIR>/scripts/confirm_gate.py" --workdir 软著 --stage code-selection --note "按模型选择确认"
python "<SKILL_DIR>/scripts/extract_code.py" --project . --selection 软著/草稿/代码文件选择.json --software-name "智慧仓储管理平台" --version "V1.0" --out-dir 软著/草稿
```

产出 `代码.md`（前30+后30 合并）与 `代码提取清单.{md,json}`。若已选不足 60 页且候选有富余，抽取脚本会停止要求补充选择。

### 5. 申请表字段（`application-fields` 门禁）

```bash
python "<SKILL_DIR>/scripts/application_info.py" --analysis 软著/analysis/project.json --code-manifest 软著/草稿/代码提取清单.json --business-context 软著/草稿/业务理解.json --software-name "智慧仓储管理平台" --version "V1.0" --out-dir 软著/草稿
```

用户补全 `申请表信息.md` 中的著作权人、开发完成日期、硬件环境等字段（也可通过 `--answers <JSON路径>` 传入），脚本校验枚举/日期/长度/500~1300 字窗口后记录门禁：

```bash
python "<SKILL_DIR>/scripts/confirm_gate.py" --workdir 软著 --stage application-fields --note "字段已补全确认"
```

### 6. 截图（仅 operation，`screenshot-method` 门禁）

用户四选一，本例选 agent-browser（宿主浏览器技能操作真实页面截图，无需额外安装）：

```bash
python "<SKILL_DIR>/scripts/confirm_gate.py" --workdir 软著 --stage screenshot-method --method agent-browser --note "宿主浏览器截图"
```

模型按操作手册模块顺序把截图落盘为 `软著/截图原始/01-登录.png`、`02-入库单.png`…，然后整理生成清单：

```bash
python "<SKILL_DIR>/scripts/shots.py" --input-dir 软著/截图原始 --out-dir 软著/截图 --method agent-browser
```

选 skip 则跳过截图，操作手册保留可见的 `【截图预留：……】` 文字占位。

### 7. 文档草稿与最终确认（`markdown` 门禁）

```bash
python "<SKILL_DIR>/scripts/manual_draft.py" --business-context 软著/草稿/业务理解.json --software-name "智慧仓储管理平台" --version "V1.0" --out-dir 软著/草稿
```

自检存在阻断问题时脚本退出，模型修正业务理解或模型稿后重跑（自检记录按真实轮次追加）；通过后停止等用户整体确认 Markdown 草稿：

```bash
python "<SKILL_DIR>/scripts/confirm_gate.py" --workdir 软著 --stage markdown --note "操作手册与全部草稿确认"
```

### 8. 正式生成

```bash
python "<SKILL_DIR>/scripts/build_final.py" --workdir 软著 --software-name "智慧仓储管理平台" --version "V1.0"
```

产出：

```text
软著/申请资料/申请表信息.txt
软著/申请资料/智慧仓储管理平台-代码.docx      （前30+后30 模式实际页数强校验为 60）
软著/申请资料/智慧仓储管理平台_操作手册.docx   （截图按清单插入）
软著/申请资料/生成报告.md
```

提交前把两个 docx 在 Word/WPS 中复核并另存为 PDF，按中国版权保护中心官网要求填报。

### 9. 合规审查（软著审查专员）

对正式生成物做登记合规复核并出具审查报告，审查结论随后由用户确认（第八道门禁）：

```bash
python "<SKILL_DIR>/scripts/review_final.py" --workdir 软著
```

干净情形的输出：

```text
OK 合规审查底稿：软著/审查/合规审查底稿.md
结论：通过（阻断 0 项，提示 0 项）
STOP_FOR_USER
NEXT_ACTION: 模型以软著审查专员身份阅读底稿与正式文件（有宿主 docx/视觉技能时抽查 DOCX 页眉、标题、截图与图纸乱码），撰写 软著/审查/审查报告.md 并呈交用户；存在阻断项时由用户决定回到对应阶段整改重跑还是停止提交。
```

随后模型撰写 `软著/审查/审查报告.md`：审查结论（通过/整改后通过/不通过）、逐项合规情况（对应底稿 R 编号）、问题与整改建议、提交前检查清单，并呈交用户。若底稿存在**阻断**项（例如某页代码不足 50 行、申请表字段超限、材料中某行代码无法回溯到项目源码、名称版本不一致、门禁失效），审查报告为“不通过”并指明回到哪个阶段重跑；**提示**项（如截图数量与预留不匹配、文本框线图建议升级 PNG）建议处理但不阻塞提交。整改一律回到对应阶段重新生成并重新确认，不得直接修改 `申请资料/` 里的正式文件。

### 10. 审查确认（第八道门禁）

用户确认审查结论后记录门禁到 `软著/审查/合规审查确认.json`：

```bash
python "<SKILL_DIR>/scripts/confirm_gate.py" --workdir 软著 --stage review --note "审查结论已确认"
```

与前七道门禁不同，这道门禁的指纹覆盖 `申请资料/` 全部正式文件与 `审查/审查报告.md`：正式材料在审查确认后被任何改动，门禁即失效，须重新审查再确认；结论为「不通过」时不允许确认，必须先整改。

确认脚本会以**当前状态**重新跑一次机器核查，不只信报告里的结论：仍有阻断项时拒绝确认；报告结论比机器结论更宽松（例如机器查出阻断项、报告却写「通过」）同样拒绝——脚本发现的问题不得降级或省略。

## 示例 B：无界面软件 → 技术方案文档（DOT + archify 混合产图）

背景：`D:\works\collector` 是设备数据采集后台服务（无界面），登记名称 **智能设备数据采集服务 V1.0**。

与示例 A 的差异：

1. **业务理解模型稿**填 `manual_kind=design` 与 `design_spec`（requirements、conditions、architecture、modules、overview、functions、api_groups、error_handling），并在 `figures` 声明图纸插槽：

```json
"figures": {
  "architecture": "digraph G { subgraph cluster_1 { label=\"接入层\"; 设备接入; 协议解析; } 数据队列 -> 存储; 存储 -> 上报; }",
  "key_1": "digraph G { 断线检测 -> 本地缓存 -> 重连补发; }"
}
```

2. **没有截图阶段**，不产生 `screenshot-method` 门禁。

3. **图纸渲染**（manual_draft 之前执行）：

```bash
python "<SKILL_DIR>/scripts/figures.py" --workdir 软著
```

默认全部按 DOT 渲染。**宿主架构图技能（archify）产图优先**：模型用 archify 为 `architecture` 插槽生成更完整的架构图，把导出图片保存为：

```text
软著/图纸原始/01-architecture.png
```

再跑同一条 `figures.py`，即可看到：

```text
OK 图纸 architecture -> 图纸/01-architecture.png（host-image）
提示：宿主技能产图优先于 DOT 渲染；插入正文前请用视觉能力复核无乱码、无遮挡
```

`key_1` 等其余插槽仍走 DOT 渲染（无 graphviz 时自动降级中文文本框线图）。图纸清单与登记的图片纳入最终确认指纹——确认后替换图片，`markdown` 门禁失效，需重新确认。

4. 其余门禁与正式生成同示例 A，最终产出：

```text
软著/申请资料/智能设备数据采集服务-代码.docx
软著/申请资料/智能设备数据采集服务_技术方案文档.docx
```

5. 正式生成后同样运行 `review_final.py --workdir 软著` 做合规审查（design 模式核查图纸而非截图），产出 `软著/审查/合规审查底稿.md`，模型据此撰写 `软著/审查/审查报告.md`；文本框线图图纸会列为提示项（建议安装 graphviz 或用 archify 产图升级 PNG）。

## 门禁失效示例（指纹机制）

`business` 门禁确认后，用户又修改了 `软著/草稿/业务理解.json` 里的一段功能描述，此时直接运行 `markdown` 门禁会被拦下：

```text
STOP_FOR_USER
NEXT_ACTION: Markdown 确认前需先处理以下事项：
- 业务理解在确认后被修改，需重新确认
```

处理方式：重新运行 `confirm_gate.py --stage business` 记录新指纹（业务理解变化影响下游草稿时，相应草稿与门禁也要重跑），再确认 `markdown`。这一机制保证正式 Word 的内容与用户确认过的内容逐字一致。
